    How this works — in four lines

    1. Every Saturday we snapshot the free fan polls: the bbnaijadaily vote widget, hand-logged rows, and official bottom-N/top-N reports from news blogs.

    2. Each observation is stored as one row in a long-format matrix, then aggregated with source-grade, sample-size and recency weights.

    3. Official ranking constraints are applied (softened where they conflict with the polls), and 1,000 bootstrap replicates quantify the uncertainty.

    4. The aggregated share IS the win probability — the 89% intervals, rank chips and podium odds all come from the same bootstrap replicates.

    Numbers are fan-poll shares — never vote counts. Full technical detail below.

    Methodology how the tally is built, start to finish Download PDF

    This is a weighted fan-poll aggregator with bootstrap uncertainty — not an official vote count and not a black box. Every published number is derived from the formulas below, and every formula is derivable by hand from the poll log.

    1 · The observation matrix

    Each poll snapshot becomes one row in a long-format table. A row records the source, its grade, its sample size, the week, and one value per housemate — and what that value means depends on what the source reported:

    obs_typewhat the source reportedstored value
    full_sharea poll with each housemate's sharea number in [0, 1]
    top_N / bottom_Nan official ranking naming leaders / bottom housemates0 / 1 flag
    rankan ordered list with no sharesan integer rank
    matrix M = one row per (source, week)
    In plain wordsa spreadsheet where each line says “this source said this about these housemates this week”.
    Whykeeping raw rows instead of one blended number means every figure can be traced to the poll that produced it, and a bad source can be down-weighted without deleting it. Rows are deduplicated latest-wins per (source, week), so a re-run can never double-count the same poll.

    2 · Recency window and weights

    Only the last 3 weeks enter. Each row gets a weight from three things: how trustworthy its source is (q), how many votes it saw (n), and how old it is (λΔt).

    row weight wk = qk · min(nk, Ncap) · λΔtk
    symbolmeaningvalue now
    qksource grade — trustworthinesswidget =1.0, transcribed =1.0, FB group =0.7, ranking channel =0.5
    nkvotes the poll sawreal votes, or a pseudo-n when hidden
    Ncapsample-size ceiling5 000
    λper-week decay0.6
    Δtkweeks between the row and now0, 1, 2 …
    εconstraint margin0.01
    Bbootstrap replicates1 000
    In plain wordsa poll with far more votes counts more; a trusted source counts more; last week counts 60% of this week, and the week before counts 36%.
    Whythe cap stops one viral widget (hundreds of thousands of votes) from drowning every other source; the decay keeps the snapshot responsive without throwing history away.

    3 · Shares are renormalised inside each poll

    Rarely do two polls list the same housemates. Each row is rescaled so its covered shares sum to 1, making sources comparable:

    row share s̃i,k = si,k Σj sj,k
    In plain wordsif a poll only listed six of nine housemates, we rescale those six to add to 100% before combining.
    Whywithout this, a source covering fewer people would look like it gave everyone a smaller share.

    4 · Aggregation — the weighted blended share

    aggregate share Si = Σk wk · s̃i,k Σk wk , full-share rows only
    In plain wordsa weighted average of every poll, where bigger and more recent polls pull the result further.
    Whythis is the published headline. It is a plain weighted mean — no softmax, no hidden function — so it can be checked with a calculator and the poll log.

    5 · Coverage — never invent a number

    If no full-share source covered a housemate this week, they inherit last week's blended share (flagged carried); a housemate never covered at all is floored at the week's minimum measured share (flagged unmeasured).

    carry-forward Si ← Si(x−1) when Si = 0
    In plain wordsif nobody polled a housemate, we carry their last known value forward rather than pretending it is zero.
    Whya silent zero would look like “no support” when it is really “no data”. Carried values are labelled everywhere they appear.

    6 · Constraints — official rankings, softened on conflict

    When official bottom-N / top-N rankings exist, they bound the shares. If a constraint agrees with the polls it applies fully; if it contradicts them, the affected shares are pulled only halfway to the bound, and the softening is logged.

    bounds bottom-N: Si ← min(Si, mout·(1−ε)) · top-N: Si ← max(Si, mout·(1+ε))
    on conflict Si ← Si + ½·(bound − Si)
    In plain wordsan official list is strong evidence, but one thin ranking report should not completely overrule thousands of votes.
    Whyhalfway pulls resolve disagreement safely instead of letting a single lower-grade row flip the standings; every adjustment is written to the run log.

    7 · Renormalise, then bootstrap the uncertainty

    After carry and constraints the shares are renormalised to sum to 1. Then the whole weighting is repeated B=1 000 times, each time resampling the poll rows in proportion to their weights (and drawing the polls' voters), giving the uncertainty band:

    renormalise Si ← Si Σj Sj
    89% interval [ Si(5.5) , Si(94.5) ] from B resamples
    In plain wordswe re-run the whole calculation a thousand times with slightly different poll samples; the range that contains the middle 89% is our uncertainty band.
    Whypoll data is thin and noisy; an interval is more honest than a single over-confident number. Constraints are rules, not votes, so every replicate applies them — which keeps the point estimate inside its own band.

    8 · From shares to the published products

    Everything else is read straight off those same 1 000 replicates — no extra machinery:

    win probability P(win)i = Si
    rank chip P(#1)i = 1B Σb 1{ rankb(i) = 1 }
    head-to-head P(A>B) = 1B Σb 1{ SA(b) > SB(b) }
    momentum ΔSi = Si(x) − Si(x−1)

    In plain words“share = chance of winning”; a rank chip is just the fraction of the thousand runs in which that housemate finished in that position.

    Reading a matchupP(A>B) above 0.90 is a clear lead, 0.60–0.90 is a lean, and below 0.60 is “too close to call” (shown as a tie).
    Whyusing the same replicates for every product means the podium, chips and head-to-head can never disagree with one another.

    9 · Gambit auto-finalists

    Housemates holding a guaranteed finale seat under the Gambit twist never enter the poll matrix (they are not in the save polls), so they carry no share and no win number. They are shown in their own strip for transparency.

    Whymixing ineligible housemates into win shares would inflate everyone's denominator and misstate the race.

    10 · What this is — and is not

    It is a transparent, reproducible aggregation of publicly available fan polls, with explicit uncertainty and a full audit trail.

    It is not an official result, a vote count, or independent sampling. Fan polls share repeat-votable mechanics and recurring voters across sites, so treat the output as a correlated fan-intensity index. Numbers are shares — never votes. Every published surface carries the “fan forecast, not official result” disclaimer.
